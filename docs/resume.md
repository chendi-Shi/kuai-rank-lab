# 简历与面试准备

项目名：**KuaiRank Lab：短视频多目标精排与曝光分布评估**

技术栈：Python / PyTorch / LightGBM / pandas / FastAPI / pytest。

## 可修改使用的简历条目

- 基于 KuaiRand-Pure 262 万真实曝光构建长播预测精排实验，设计全局时间切分及用户/视频/作者前日历史特征，排除未来统计泄漏；统一 25 万训练样本完成 LR、LightGBM、DeepFM、Shared-Bottom、MMoE 与容量匹配对照，共 14 个运行，神经模型各 3 个 seed。
- 结合用户级 GAUC、分桶诊断和 paired bootstrap 评估多任务收益，发现 MMoE 改善随初始化变化，参数量匹配后仍无稳定优势；验证集预选 LR 的普通测试 AUC 为 0.7514，形成可追溯的测试冻结和产物指纹协议。
- 针对普通与随机曝光的概率分布变化，在独立校准集拟合 Platt scaling；随机测试 LogLoss 从 0.4833 降至 0.2787，相比正例率常数基线进一步降低 5.84%，同时保留 AUC，明确区分校准收益与排序提升。
- 实现 FastAPI 批量候选评分和小批次编码优化，HTTP 输出与离线预测一致；本机 CPU 的 24 候选、4 并发压测 HTTP p95 为 123 ms，完成 28 项数据协议、指标与推理测试。

## 面试必须讲清的内容

1. 为什么全局时间切分？为什么用户历史只用前日？同日请求顺序不可靠、反馈可能延迟，前日快照是保守可复现的近似；测试回放可见前日普通策略反馈，不是闭环策略仿真。
2. 哪些特征会泄漏？整月视频统计包含未来行为，无时间戳的画像快照无法保证请求时可用，当前曝光播放时长和反馈不能进输入。
3. MMoE 如何工作？各专家产生表示，各任务 gate 加权专家表示后进入任务 tower；辅助任务可能帮助或造成负迁移。理解共享参数的梯度，不要只背结构名字。
4. 怎样证明收益不是容量？对照单任务 DeepFM 总参数量，保持相同训练事件与编码器。三个 seed 加用户级 bootstrap 分别回答训练波动和评估样本波动。
5. 为什么复杂模型没赢？当前训练样本、强历史特征及超参数可能让 LR 有竞争力。学习率、正则、数据量与任务权重需要进一步消融，现有实验不支持架构普遍劣势。
6. 为什么校准能降低 LogLoss 而 AUC 不变？logit 仿射变换为正斜率时保留次序，但改变概率尺度。必须比较目标流量平均正例率基线，避免把简单先验修正误报为排序优化。
7. 为什么不把随机曝光对比叫因果去偏？日期相同不意味着用户、视频及场景支持集相同；当前只做分布变化诊断和有监督校准，没有 IPS 权重或因果识别。
8. 为什么 NDCG 看起来很高？Pure user-day 有大量一候选组。限制至少 5 个候选且有正负反馈可增加解释性，但仍只是日志曝光集合内排序。
9. 服务性能怎么算？当前只测本机模型候选评分，不含召回及特征获取。固定请求和热模型数据不能等同于线上端到端吞吐。
10. 与广告/搜索岗位有什么关系？特征时序、概率估计、多任务共享、偏移诊断、校准和推理通用；本项目标签不是广告 CVR，没有 query-document 搜索标签，不应声称做过广告转化或搜索相关性系统。
